IoT device identity and network incidents

A network that cannot tell which device sent a packet, or whether that device was tampered with, cannot defend itself. We identify devices and attacks from packet headers alone.

Fingerprinting IoT devices from a single packet

With Dr. Ahmet Aksoy and UCM students, we identify an IoT device's vendor and type from the header fields of just one TCP/IP packet, so vulnerable devices can be found and isolated quickly. We compared feature selection methods from four families (filter, wrapper, embedded and search optimization) to learn which header fields carry the fingerprint.

Identifying network attacks with a genetic algorithm

Instead of experts hand-picking traffic features, a genetic algorithm evolves the feature subset: each candidate is scored on how accurately a classifier separates attack from normal traffic and on how few features it needs. The result detects DNS botnets, two kinds of denial-of-service floods and NMAP OS scanning. The code and data are public.

Hybrid blockchains for IoT

With my M.Sc. student Ahmed Alkhateeb, we systematically reviewed how hybrid blockchain platforms secure IoT data. Ethereum dominates, and most systems pair the ledger with cloud or fog computing.

Where this is going

Combining traffic fingerprints with ledger-based attestation, so a network knows which devices are present and whether any has been tampered with, cheaply enough for resource-constrained IoT deployments.

Open research questions

Questions this work leaves open. They are directions, not results; each links to the planned project that takes it up.

  1. How can traffic-fingerprint baselines be kept current cheaply enough for resource-constrained IoT deployments?

    Why it is open
    Device behavior drifts with firmware updates and usage, and constrained networks cannot afford constant retraining.
    Taken up in
    ledger identity · leak-free benchmarks

  2. Can devices and applications be identified from encrypted-flow metadata alone, without decrypting payloads?

    Why it is open
    Most traffic is now encrypted, so sizes, timing and handshakes are what a privacy-respecting network can still use.
    Taken up in
    encrypted traffic

  3. Can a device's radio signature back up its traffic fingerprint, so that a clone has to fake both?

    Why it is open
    Header fingerprints identify a device's type from its packets. A cloned device can copy packets more easily than it can copy the flaws of another radio.
    Taken up in
    RF fingerprinting

Start here

A concrete first month for a student joining this work. Each step builds on the one before.

  1. Step 1Read our ICISSP and Electronics papers below.
  2. Step 2Capture traffic from two of your own devices with Wireshark and extract header fields with Scapy.
  3. Step 3Train a nearest-profile classifier on CICIoT2023 headers and check which fields it leans on.
