Securing the EV charging network

Electric-vehicle chargers are networked computers connected to the power grid. If an attacker controls many of them at once, switching them together could stress the local grid. This project studies those attacks and how to detect them early.

Why this matters

Public chargers talk to the car, to the operator's servers and to payment systems, and the operator can start and stop charging remotely. Security reviews of this ecosystem have found weaknesses at each of those links. The grid side is what makes it more than a data breach: one compromised management server can reach thousands of chargers, and switching them together changes the load on a neighborhood feeder in seconds.

This is a new direction for my group that joins two existing lines: vehicles as networked systems (my dissertation and the GM driver-identification work) and machine-learning detection of anomalies in network and sensor data (Electronics 2024; EPJ Quantum Technology 2025).

Research questions

  1. How much can a coordinated attack on many chargers move the load on a local grid, and which attack patterns matter most?

    Hypothesis
    Switching a modest share of chargers at once produces load swings large enough to matter for a local feeder, and the timing of the switching matters more than its size.
    How we would test it
    Simulate charging stations on standard distribution test feeders with realistic charging sessions, and measure voltage and load violations as the share of compromised chargers grows.

  2. Can anomaly detection on charging sessions and load data catch such attacks early, with few false alarms?

    Hypothesis
    Coordinated switching leaves sharp, synchronized steps that normal charging does not; a detector on per-station session data catches them sooner than one on total load alone.
    How we would test it
    Train detectors on simulated normal days and test them on graded attacks, reporting detection delay and false alarms per day.

  3. Where are the weak points in the protocol stack between charger, operator and vehicle, and which hardening steps matter most?

    Hypothesis
    The management link between charger and operator is the easiest place to start a coordinated attack, because one compromised server reaches many chargers.
    How we would test it
    Model the charger management protocol in a lab test bed with open-source charger and server software, and run a structured threat analysis with attack trees.

Expected contributions

  • A simulation test bed that couples charging stations with a distribution feeder model.
  • Detectors for coordinated charging attacks, with detection delay and false alarms.
  • A threat analysis of the charger management link with concrete hardening steps.

Approach

  1. Model the gridAttach simulated charging stations to standard distribution test feeders.
  2. Model chargingGenerate realistic sessions from public charging datasets.
  3. AttackSimulate coordinated switching and data-manipulation attacks of growing scale.
  4. DetectTrain detectors on station and feeder data and measure delay and false alarms.
  5. HardenBuild a lab test bed with open-source charger and server software and analyze the management link.

All attacks run in simulation or in an isolated lab test bed, never on real chargers or grids.

Discussion

If it works

An early warning when many chargers act together in a way that could stress the grid.

Where it could fail

  • Real charger data is hard to obtain, so the work relies on simulation and public data.
  • Legitimate demand spikes can look like attacks.

How we will know

Time to detect and false alarms in grid simulations with coordinated and normal charging.

A concrete first month for a student joining this work. Each step builds on the one before.

  1. Step 1Read the papers below.
  2. Step 2Load ACN-Data sessions and build a day of charging load.
  3. Step 3Attach that load to a pandapower test feeder and add coordinated switching.
  4. Step 4Read the OCPP overview and list which messages could start or stop many sessions.
