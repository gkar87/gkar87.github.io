Spotting intruders on the car's internal network

Inside every car, dozens of computers talk over one shared bus with no sender authentication. This project builds detectors that notice when a message on that bus does not belong there.

Why this matters

Researchers have shown that an attacker who reaches a car's internal network can control brakes, engine and locks. Messages on that network carry no proof of who sent them, so detection has to come from patterns: when messages arrive, what they contain and which control unit produced them. My PredriveID work with General Motors Research read exactly this kind of bus data to tell drivers apart, using low-cost hardware. This project turns the same skills toward catching intrusions.

Research questions

  1. How well do timing-based, content-based and learning-based detectors catch injection, flooding and impersonation attacks on public in-vehicle datasets?

    Hypothesis
    Timing detectors catch flooding and most injections cheaply; impersonation that keeps the rhythm needs content or sender features.
    How we would test it
    Benchmark the three families on public in-vehicle datasets with one common split and per-attack metrics.

  2. Do detectors trained on one car still work on another model, or after a software update changes the message rhythm?

    Hypothesis
    Learned detectors transfer poorly across vehicles; timing baselines recover after recalibrating on a short drive.
    How we would test it
    Train on one vehicle or software version, test on another, and measure how much clean driving each detector needs to recover.

  3. Can a detector small enough for an in-vehicle gateway also say which control unit sent the bad message?

    Hypothesis
    Timing and electrical traits together can point to the sending control unit for many attacks.
    How we would test it
    Add sender attribution and test it on data with known sources, then profile it on gateway-class hardware.

Expected contributions

  • A common benchmark of in-vehicle intrusion detectors across attack types.
  • Measurements of how detectors transfer across vehicles and software updates.
  • A gateway-sized detector that also points to the sending control unit.

Approach

  1. DatasetsStart from public in-vehicle attack datasets, then log our own drives with an OBD-II interface.
  2. BaselinesReimplement entropy, clock-skew and neural detectors from the reading list.
  3. Cross-car testsTrain on one vehicle or time period, test on another.
  4. Lightweight modelShrink the best detector for a low-cost embedded board.
  5. ReportDetection rate, false alarms per hour of driving and attribution accuracy.

Start here

A concrete first month for a student joining this work. Each step builds on the one before.

  1. Step 1Read the papers below.
  2. Step 2Download the HCRL Car-Hacking dataset and plot the gap between frames for each identifier.
  3. Step 3Write a timing detector and report detection and false alarms for each attack type.
  4. Step 4Replay a log on a virtual CAN interface with can-utils to test your detector live.

Tools and data

  • HCRL Car-Hacking datasetCAN traffic from a real car with injection attacks.

Papers to read first

  1. Experimental security analysis of a modern automobile
    K. Koscher, A. Czeskis, F. Roesner, S. Patel, T. Kohno, S. Checkoway, D. McCoy, B. Kantor, D. Anderson, H. Shacham, S. Savage
    IEEE S&P, 2010
    The paper that showed what an attacker on the car's network can do.
    Read
  2. Entropy-based anomaly detection for in-vehicle networks
    M. Müter, N. Asaj
    IEEE Intelligent Vehicles Symposium, 2011
    An early, simple detector that is still a useful baseline.
    Read
  3. Fingerprinting electronic control units for vehicle intrusion detection
    K.-T. Cho, K. G. Shin
    USENIX Security, 2016
    Uses the timing of periodic messages to fingerprint the sender.
    Read
  4. GIDS: GAN based intrusion detection system for in-vehicle network
    E. Seo, H. M. Song, H. K. Kim
    PST, 2018
    A learning-based detector that can flag attacks it never saw.
    Read
  5. In-vehicle network intrusion detection using deep convolutional neural network
    H. M. Song, J. Woo, H. K. Kim
    Vehicular Communications, 2020
    A deep detector evaluated on a widely used public dataset.
    Read
  6. PredriveID: Pre-trip driver identification from in-vehicle data
    G. Kar, S. Jain, M. Gruteser, J. Chen, F. Bai, R. Govindan
    ACM/IEEE SEC, 2017
    How we collected and used in-vehicle bus data.
    Read
