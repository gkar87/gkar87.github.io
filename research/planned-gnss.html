Catching GNSS spoofing with the car's own sensors

Can a car notice that its GPS is lying, using only the data it already has? This project builds a lightweight spoofing detector from the vehicle's own motion data.

Why this matters

A GPS jammer blocks satellite signals; a spoofer is worse, because it feeds the receiver fake signals and quietly moves the car to the wrong place. Researchers have shown that spoofed routes can fool location tracking on real roads and can take over the sensor-fusion localization used in autonomous driving. Meanwhile every modern car already measures how it actually moves: wheel speeds, steering angle and yaw rate travel on its internal data bus.

My earlier work located cars that jam GPS from the roadside (ACM CCS 2014) and read in-vehicle data to identify drivers (ACM/IEEE SEC 2017). This project joins the two: check every GPS fix against the car's own motion, on hardware cheap enough to ship.

Research questions

  1. How quickly can wheel-speed, steering and yaw-rate data expose a GPS position that disagrees with how the car really moved, and at what false-alarm rate?

    Hypothesis
    Crude position jumps show up within seconds; slow drift is caught only once it outgrows the dead-reckoning error, which itself grows with distance driven.
    How we would test it
    Replay recorded drives with injected attacks of graded speed, and plot detection delay against false alarms per hour for each attack type.

  2. Can the detector run on a phone or an in-vehicle processor in real time, with a memory and power budget an automaker would accept?

    Hypothesis
    A Kalman-filter residual test is cheap; any learned component is what has to be sized carefully.
    How we would test it
    Replay drives in real time on a phone and an embedded board, and profile latency, memory and energy per fix.

  3. How does a careful attacker who drifts the position slowly, or follows the real road network, evade it, and what does it take to catch them?

    Hypothesis
    To stay under the alarm, a road-following attacker has to mirror the car's real turns, which limits how far it can take the car.
    How we would test it
    Build an adaptive attacker that knows the detector, and measure how far off route it gets before the alarm.

Expected contributions

  • A spoofing detector that uses only data the car already has, with its code.
  • A set of recorded drives with simulated attacks, from crude jumps to road-following drift, for others to test against.
  • Measured detection delay, false alarms and phone run time for each attack type.

Approach

  1. Collect drivesLog GNSS fixes and bus data with an OBD-II dongle and a phone, as in PredriveID.
  2. Simulate attacksReplay recorded traces with injected spoofing paths, from crude jumps to slow, road-following drift.
  3. Model motionDead reckoning and a Kalman filter turn bus data into an independent path.
  4. DetectCompare the two paths with a residual test and a small learned model.
  5. MeasureTime to detect, false alarms per hour, and run time on a phone.

All spoofing is simulated in recorded data or in a shielded lab. Transmitting on GPS frequencies on the road is illegal and is never part of this project.

Start here

A concrete first month for a student joining this work. Each step builds on the one before.

  1. Step 1Read the five papers below, starting with ours.
  2. Step 2Download the comma2k19 sample and compute dead-reckoning position from wheel speed and steering.
  3. Step 3Add a synthetic drift to the GNSS track and plot the gap between the two paths over time.
  4. Step 4Set an alarm threshold from normal driving and report detection delay for your drift.

Papers to read first

  1. GNSS spoofing and detection
    M. L. Psiaki, T. E. Humphreys
    Proceedings of the IEEE, 2016
    The standard survey: how spoofing works and the families of defenses.
    Read
  2. On the requirements for successful GPS spoofing attacks
    N. O. Tippenhauer, C. Pöpper, K. B. Rasmussen, S. Capkun
    ACM CCS, 2011
    What an attacker must control to move a victim, and why that is hard.
    Read
  3. Security of GPS/INS based on-road location tracking systems
    S. Narain, A. Ranganathan, G. Noubir
    IEEE Symposium on Security and Privacy, 2019
    Spoofing that follows the road network, the attacker this project must beat.
    Read
  4. Drift with Devil: Security of multi-sensor fusion based localization in high-level autonomous driving under GPS spoofing
    J. Shen, J. Y. Won, Z. Chen, Q. A. Chen
    USENIX Security Symposium, 2020
    Shows sensor fusion alone is not a defense, so detection has to be designed in.
    Read
  5. Detection of on-road vehicles emanating GPS interference
    G. Kar, H. Mustafa, Y. Wang, Y. Chen, W. Xu, M. Gruteser, T. Vu
    ACM CCS, 2014
    Our earlier work on GPS interference from vehicles.
    Read
  6. PredriveID: Pre-trip driver identification from in-vehicle data
    G. Kar, S. Jain, M. Gruteser, J. Chen, F. Bai, R. Govindan
    ACM/IEEE SEC, 2017
    How we collected and used in-vehicle bus data with low-cost hardware.
    Read
