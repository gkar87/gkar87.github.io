Leak-free benchmarks for IoT traffic classifiers

Many intrusion-detection and device-fingerprinting papers report near-perfect accuracy. This project measures how much of it survives once shortcuts in the data are removed.

Planned project · core area · open to new graduate students

Why this matters

Machine learning on network traffic often learns the wrong thing. A model can score 99% because a field such as an IP address or a timestamp tells it which capture a packet came from, not because it understands the device or the attack. Security researchers have documented such pitfalls across top venues, and the widely used CICIDS2017 dataset turned out to contain labeling and feature-extraction errors.

My group has published device fingerprinting from packet headers (ICISSP 2024) and genetic-algorithm feature selection for incident detection (Electronics 2024). This project turns the same critical eye on that kind of work, our own included, and produces a benchmark that other groups can trust.

Research questions

  1. Which packet and flow features act as shortcuts in popular IoT and intrusion datasets, and how can they be found automatically?
  2. How much accuracy do published-style pipelines keep under time-based splits, unseen networks and unseen devices?
  3. Which features stay useful after the audit, and can a model built on them run on a home or campus gateway?

Approach

  1. ReproduceRe-run our fingerprinting and feature-selection pipelines on public datasets.
  2. AuditSearch for shortcut features with ablation and simple one-feature models.
  3. Re-splitEvaluate with time-based, network-based and device-based splits.
  4. RebuildSelect features again under the strict protocol and size a gateway model.
  5. ReleasePublish the protocol, code and cleaned splits for others to use.

Skills you will use and learn

  • Python, pandas, scikit-learn
  • Wireshark and Scapy
  • Experiment design
  • Feature selection
  • Reproducible research

Papers to read first

  1. Outside the closed world: On using machine learning for network intrusion detection
    R. Sommer, V. Paxson

    The classic argument for why intrusion detection is harder for ML than it looks.

  2. Dos and don'ts of machine learning in computer security
    D. Arp, E. Quiring, F. Pendlebury, A. Warnecke, F. Pierazzi, C. Wressnegger, L. Cavallaro, K. Rieck
    USENIX Security Symposium, 2022

    Read
  3. Troubleshooting an intrusion detection dataset: the CICIDS2017 case study

    IEEE Security and Privacy Workshops, 2021
    What went wrong inside a dataset everyone uses.

    Read
  5. N-BaIoT: Network-based detection of IoT botnet attacks using deep autoencoders
    Y. Meidan, M. Bohadana, Y. Mathov, Y. Mirsky, A. Shabtai, D. Breitenbacher, Y. Elovici
