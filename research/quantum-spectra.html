Quantum machine learning for Raman spectroscopy

Hybrid quantum-classical models are not only for network traffic. Raman spectra, the light fingerprints of molecules, are a natural test bed: one-dimensional, noisy and costly to label.

The question

Can hybrid quantum-classical models classify Raman spectra, the light fingerprints of molecules?

Why it matters

Spectra are one-dimensional, noisy and costly to label, which makes them a natural test bed for small quantum models.

What we found

A quanvolutional network classified COVID-19 from the Raman spectra of serum, and a hybrid network classified weathered microplastics while running on a real IonQ quantum processor.

What a quanvolution layer does

A classical convolution slides a small filter over its input. A quanvolution layer slides a small quantum circuit instead: each window of input values is encoded as rotations of a few qubits, the circuit entangles them, and the measured expectation values become a new feature map that a classical network then reads. The live figure above computes one such feature exactly for a toy circuit.

  1. Windowa few neighboring spectrum values
  2. Encodeeach value rotates one qubit
  3. Entanglea small fixed or trained circuit
  4. Measureexpectation values become features
  5. Classifya classical network reads the feature map

COVID-19 from the Raman spectra of serum

In IEEE Access (2025), with S. S. Dutta, S. Sandeep, S. Sridevi, R. Mistry and J. Ortega, we turned Raman spectra of human serum into wavelet scaleograms and classified COVID-19 with a quanvolutional neural network, comparing it with classical CNNs. It is the same wavelet-to-quantum pipeline we use for intrusion detection, applied to light instead of traffic.

100%precision of our network: no healthy sample was flagged
97.73%recall: share of COVID-19 samples found

Weathered microplastics on a real quantum processor

In AVS Quantum Science (2026), with H. G. Kulkarni, A. R. Banerjee, T. Mandloi, S. Sridevi and S. Geetha, a classical-quantum neural network with dual-channel feature extraction ran on an IonQ quantum processor to classify weathered microplastics from their Raman spectra. Running on hardware, not only a simulator, is what makes the results a test of today's machines.

Discussion

What it shows

Raman spectra are a natural test bed for small quantum models, and the microplastics study ran its hybrid network on real quantum hardware, not only in simulation.

Where it falls short

  • Spectral datasets are small, so results depend on careful validation.
  • Time on quantum hardware is limited and costly, so the number of runs is small.
  • The classical parts of the pipeline do much of the work; isolating what the quantum part adds needs matched baselines.

What it means

Real-hardware runs are where the field needs evidence, and they are now part of how my group works.

Open research questions

Questions this work leaves open. They are directions, not results; each links to the planned project that takes it up.

Start here

A first month for a student joining this work, in 3 steps. Do them in order: each one uses what the one before produced.

Goal for the month: A rebuilt quanvolution filter that runs on a simulator and, if possible, on real quantum hardware.

Before you start: setup for every project
  1. Set up a workspace. Create a private Git repository for the project with folders for data/, src/, figures/ and notes/. Make a Python virtual environment (python -m venv .venv) and record every package you install in requirements.txt.
  2. Keep a lab notebook. Add a dated entry to notes/log.md each time you work: what you ran (the exact command), what came out, and what surprised you. This log is the first thing to share when you ask for help, and most of your paper's method section comes from it.
  3. Make every number reproducible. Fix random seeds, write down the dataset version and how you split it, and keep the script that produced each figure next to the figure. If you cannot regenerate a number with one command, it is not finished.
  4. Stay legal and ethical. Work only with public datasets, data you recorded yourself with everyone's consent, or systems you own. Never test an attack on a network, car, radio band or service that is not yours, and follow the safety note on this page.
  5. When you get stuck. Spend about an hour, then write down what you tried, what you expected and the exact error or plot, and ask. A precise question is much easier to answer than "it does not work".
  1. Step 1 · Week 1Redraw the pipeline
    • Read the papers below.
    • Redraw the quanvolution pipeline by hand: input spectrum, how a window becomes qubit rotations, the circuit, the measured outputs, and the classifier.

    You are done when your drawing names every step and the size of the data between steps.

  2. Step 2 · Weeks 2 and 3Rebuild the filter
    • In PennyLane, write a one-dimensional quanvolution filter that slides over a spectrum.
    • Apply it to a public spectrum and plot the input next to the filter's outputs.

    You are done when the filter runs on the default simulator and your plot shows its outputs.

  3. Step 3 · Week 4Simulator vs hardware
    • Make a free IBM Quantum account and run the same small circuit there through Qiskit.
    • Compare the hardware outputs with the simulator for the same input, and note the queue time and number of shots.

    You are done when you have a side-by-side plot and a paragraph on where noise changed the result.
